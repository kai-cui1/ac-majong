### 3.1 听牌型与预览的一致性（2026-09-21 文档修订）

- **标准型1独（1台）**：胡前有多于一种不同胡张（**单听优先：仅一种胡张→独独，即使新胡张可作将＋卡张的多种摆法并存也不升级，2026-09-21 定案**），针对实际或预览候选的新胡张，整手至少一种合法胡牌拆解及该牌归属允许它作将牌，或作同花色顺子中间的卡张；不再以“手上已有该牌”为充分条件。
- **对碰（1台）**：两组可胡对子，胡其中一组的牌补成刻、另一组作将；与1独互斥、不并存、不重复计台。标准型独独仍按单一结构听张处理（单听一律独独），不把多面听中可作卡张的路线算成独独。
- **八对半三种特殊听法（已确认）**：胡手头只有1张的单张补成对→独独2台；胡前5对＋2刻、胡任一刻的第四张→1独1台；胡前8对、胡任一对的第三张→1独1台。预览及结算按同一特殊分支处理，不以标准型作将/卡张或听张数改判；两刻子补第四张不是对碰。
- **FR-辅助-02/03**：听牌型由完整结构听张及整手拆解判定，再逐候选胡张算分与门槛过滤；不能用过滤后的单张提示把多面听误判为独独。预览与真实结算使用同一规则，某张听张含1独不意味着全部听张都含1独。
- **边界不变**：FR-对局-22 的保底区继续排除独独/1独/对碰；本批不新增按听张分行等UI布局，不改胡牌门槛。
- **验收参照**：`23445` 胡3可作 `2(3)4+345`，算1独；`44556` 胡6只可作 `456+45(6)`，不算1独。完整固定副与将的补全、其余正反例及已定案边界（单听优先）见 [台数计算规格书](../3-技术文档/AC麻将-台数计算规格书.md) §9.4/§9.5。
- **实施状态**：新口径已于 BL-029 落地引擎（classifyWait 单听优先＋hasPairOrKanWitness 整手见证＋isDuiPeng 纯双碰门控；recognize.waitType 八对半三型分支），engine 189／game-server 117／client-core 100 测试绿；预览与结算同源。

| 环节 | 输入与展示 | 进入下一步 |

| 轮到某家 | 从房主沿开始时的下手座序轮转；真人 10000ms 输入、Bot/离线/托管 600ms 准备；其余禁用 | 接受一次操作或自动代操作后进入滚动 |

| 局间摸牌位 | 开关启用时当前庄家输入→1200ms 滚动→3000ms 结果；四卡显示实际子数、庄子分明 | 完整结果期结束后才建下一局；关闭开关不进入此仪式 |

- **入场与指代**：新仪式仅在首个输入步骤开始的250ms内淡入；重复广播、后续步骤及中途重入直接保持当前显示，不重新淡入。卡片昵称主显且保留独立「我」角标；操作提示、排名、庄家与上子说明中的同名玩家追加当前风位，自己追加「我」，避免出现无法区分的「机器人→机器人」。原型长昵称已有 `title` 完整名入口；Cocos 已实现悬停/点击昵称显示完整名 Tooltip，2秒后自动关闭，也可移开或点击提示关闭；不拉宽卡片、不增加用户确认步骤、不暂停仪式倒计时。
- **视觉与信息**：选位骰终值全桌一致，不从总和反推骰面；待重掷者滚动时旧骰面保留于卡内「上次」行，新滚动骰在主骰区。四家总览保持到该阶段结束，输入/滚动/结果/汇总以文案与状态标识区分，不能仅靠颜色。最大者、名次及最终选位顺序只能自无待决组的最终 `summary-ranking` 起展示，不能由旧 `order` 或重掷队列暂时清空推断。
- **逐轮淘汰定序（2026-09-21 修订）**：`resolveSeatingRolls`/原型 `cerSummarize` 维护有序槽位表（已定序座位 + 待决并列组）；每轮仅待决组掷骰并在组内判同点，已定序者不再参与任何判重或比大小（含其点数与重掷者新点数撞点亦不触发其重掷）；并列组在其预留名次块内由后续轮定序，重掷者新点数不与已定序者比大小。展示门控不变：最后一次重掷的 result 不宣布最终名次。

| 原型状态 | 卡片最大者/名次 | header / 排名说明 |
|---|---|---|
| `roll` 的 `input / rolling / result`（含任意连续重掷） | 一律不显示最终名次、最大者及其 `max-roll` 高亮，即使旧 `order` 非空且 `rerollIds` 已空；已落定与当前操作标记照常 | 重掷进行中、仅待决组点数待比较，不称最终「选位顺序」，不把旧顺序当结果 |
| `roll + summary-reroll` | 不确认最终名次或最大者 | 可列「同点未决 · 待决组本轮顺序」及待重掷者 |
| `roll + summary-ranking`（全体无同点）及后续选座阶段 | 显示最终名次与最大者，最大者金色高亮 | 显示最终选位顺序；落座汇总改报实际落座 |
| 后续定庄 / 局间罗盘 | 沿用实际风位与子数，独立显示庄家身份；不新增排名榜 | 定庄/开牌点说明，不混用选位排名与庄家身份 |

- **主钮与选座钮**：非选座阶段主钮始终可见，仅自己真人输入期可用；非自己输入保留禁用「等待当前玩家」，滚动保留禁用「掷骰中…」。选位 `result` 为禁用「查看结果」，定庄/局间 `result` 为禁用「即将自动发牌」，两者均为状态展示而非额外确认；非选座 summary 为禁用「仪式进行中…」，时钟使用独立74px槽。选座输入期及落座 `summary-seated` 保留四个选座钮；非本人输入或落座汇总时全禁用，选定座保留金色描边/文字/底色/光晕，不能用删除按钮代替禁用态。
- **风徽与庄徽分带**：罗盘卡仍为 118×46、面板仍为 640×330，标题/主体/说明/输入预算不变。风位圆徽保留 `.scard .wind` 的 `top:-8px; right:-6px; width:20px; height:20px`，Cocos 卡中心相对坐标 **x55、y21**；庄徽从仪式覆盖样式的 `top:0; right:-35px` 移为 **`top:auto; bottom:0; right:-35px`、高14px**，Cocos 卡中心相对坐标 **x76、y-16**，避免两徽边缘重叠。
- **本轮验证方法与边界**：原型专项 agent 的 **10 scenario / 131状态 + 6门控** 为 JS/节点替身验证，非 Browser 视觉；UI/client-core 100项为 AST 真实生产类 + 严格 mock，非 GPU。浏览器连续三轮目标 turn 均 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`、hidden/attached=false，用户打开后仍不可用；`window.open` 返回 false、rAF 暂停导致 Cocos 无 scene，不能生成必要验收证据。实机、真实双端与截图仍未完成；本次仅文档回填，不操作 Browser、启停服务或重跑验证，用户8080未重启。
- **定庄说明与物理墙**：正文只报昵称、庄家和上子结果，不展示算法公式；墙条从**视觉右端**向左编号，右端 N 组为跳区、第 N+1 组金框开摸；跳区仍为常色牌背，不当作已摸。random 模式以「随机牌墙，不展示物理开牌位置」替代墙条。预计子数与最终计子同源，避免结果展示时重复加子。

- 本局结束（有人胡 `settled` 或荒庄 `exhaustive`）→ 弹结算浮层（台数明细 + 积分变动）。
- **续局由客户端驱动**：玩家查看结算后点「下一局 ▶」推进；服务端设**相位守卫**（仅本局已结束时受理，防重复推进）。
- 打满局数上限（`maxRounds`）→ 进入「对局结束」，展示总战绩、可「再来一局」（见 [05-结算与积分战绩.md](./05-结算与积分战绩.md)）。
