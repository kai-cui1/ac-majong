## 1. 模块目标

登录后的落脚点与总入口：让玩家在一步之内**创建房间**或**加入房间**，并展示个人信息、版本与规则入口。轻社交、无匹配等待——所有对局都从房间开始。

## 2. 功能需求（FR-大厅）

| 编号 | 需求 | 优先级 | 状态 |
|---|---|---|---|
| FR-大厅-01 | 主界面两个核心入口：**创建房间** / **加入房间** | P0 | ✅ M-C：两入口 → 弹窗 → 创建/加入 → 进入等待页 |
| FR-大厅-02 | 展示玩家昵称头像、版本号、公告位 | P1 | 🟡 昵称/ID 已显示（真实资料）；头像/公告位待补 |
| FR-大厅-03 | 规则说明入口（内置《游戏规则》可查看，取自业务基线） | P1 | ❌ 待实现（规则页见 [08-规则页与设置.md](./08-规则页与设置.md)）|

## 3. 交互与页面

### 3.1 大厅页（P2）

- **顶部用户条**：头像 + 昵称 + `ID: <userId>`（登录后真实资料，见 [01-登录与身份.md](./01-登录与身份.md)）。
- **主视觉**：品牌标题「AC 麻将俱乐部」+ 中式背景（深绿桌布 / 红木，见前端基座设计令牌）。
- **两大入口**：`创建房间`（主按钮）/ `加入房间`（次按钮）。
- **辅助**：规则说明入口、版本号、公告位（可空）。
- **返回登录**：断开当前连接（`disconnect`）后回登录页。

### 3.2 创建房间弹窗（P3）

- 选择**局数上限**：`4` / `8` / `16` 局 / **`不限`**（D-23）。
  - **不限**：不设上限、无限续局，直到房主手动解散或退出（语义与散场规则详见 [03-房间系统.md](./03-房间系统.md) FR-房间-01/05）。
- 确认 → 服务端建房（`rooms` 落库）→ 生成 6 位房间号 → 进入房间等待页（房主视角）。
- 房主进入等待页后可选择「等待真人加入」或「放入 1~3 个 Bot 陪玩」（见 [03-房间系统.md](./03-房间系统.md) FR-房间-08）。

### 3.3 加入房间弹窗（P4）

- 输入 **6 位房间号**（或点微信分享卡片携带房号直接进入，分享 → M-K）。
- 校验：房间存在、未满 4 人、未开始 → 进入房间等待页（玩家视角）；否则按原因提示「房间不存在 / 已满员 / 对局已开始」。

## 4. 关键流程

```
登录成功 → 大厅（显示真实资料）
 ├─[创建房间]→ 选局数上限 → 服务端建房 → 房间等待页(房主)
 └─[加入房间]→ 输房号/点分享 → 校验可加入 → 房间等待页(玩家)
```

> 房间创建/加入的服务端处理（`create`/`join` 指令、补 Bot、座位分配）见 [03-房间系统.md](./03-房间系统.md) 与 [`../3-技术文档/AC麻将-服务端网关与房间.md`](../3-技术文档/AC麻将-服务端网关与房间.md)。

## 5. 依赖与边界

- **依赖**：登录与身份（进入大厅前置）；前端基座（`UiKit`/`Theme`/`SceneRouter`）；网络层（`create`/`join` 指令）。
- **边界（不在本模块）**：房间等待页与生命周期归 [03-房间系统.md](./03-房间系统.md)；规则页内容归 [08-规则页与设置.md](./08-规则页与设置.md)；个人资料/战绩页归 [05-结算与积分战绩.md](./05-结算与积分战绩.md)。
