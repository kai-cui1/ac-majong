## 1. 模块目标

给对局提供**可选打法、可分难度、可扩展**的 AI 机器人，覆盖三类场景：**房主陪玩**（真人不足时补位、练习对手）、**断线托管**（掉线代打，保守不吃亏）、**开发期补齐**（联调自动填位）。核心产品价值：

1. **可扩展**：一种"打法"= 一个可插拔策略，新增打法（如"追求大牌""稳健高手"）不改动房间/对局链路。
2. **可选**：房主添加机器人时可为其指定打法，玩家能看到对手是"什么风格"。
3. **合规可信**：机器人只走引擎给出的合法动作，算分/听牌/胡牌判定与真人同源，**绝不诈胡**（受最小胡 6 台门槛约束）。
4. **拟人**：保留决策延迟与适度随机，不"秒出、机械"。

> **铁律**：AI 只做"在合法动作里选哪个"的决策；合法性、算分、听牌/胡牌判定一律复用 `@ac-majong/engine`（`previewTai` 已内建最小胡 6 台门槛过滤，可防诈胡），AI 侧不另立规则口径。

## 3. 交互与页面

### 3.1 机器人打法选择面板（房间等待页 P5 增补）

- **触发**：房主在等待页点「🤖 添加机器人（n/3）」→ 弹出**打法选择面板**（居中弹层，844×390 横屏内）。
- **面板内容**：
  - 标题「选择机器人打法」+ 副文案「不同打法风格与强度不同，可随时为每个机器人单独指定」。
  - **打法列表**（纵向卡片，见 §4 档案）：每张卡 = 打法名 + 一句话风格描述 + 状态标签（`可选` / `敬请期待`）。
  - 选中态：金色描边 + 透金底（对齐现有建房弹层「局数单选」选中样式）。
  - 锁定态（P2+ 打法）：整体置灰、右上角「敬请期待」徽标、不可点。
  - 底部：`取消` / `添加`（确认）双按钮；「添加」置灰直至选中一个可用打法。
- **确认后**：新 Bot 入座空位，座位标签显示「Bot · {打法名}」；「添加机器人」计数 +1（上限 3）。
- **默认选中**：面板打开时默认高亮「最大概率打法」（P1 推荐档）。
- **移除**：房主点击 Bot 座位打开「修改机器人打法」弹层，底部提供「移除」按钮（`removeBot` 腾位给真人）；与「改打法」共用同一弹层入口（add 模式无移除钮，modify 模式有）。
- **修改已添加 Bot 的打法**：房主点击 Bot 座位（「✎ 改打法」）→ 复用打法选择面板（标题「修改机器人打法」、预选当前打法）→ 确认后更新该 Bot 打法与座位标签。

### 3.2 座位卡机器人标识（P5 微调）

- 机器人座位标签由「Bot · 保守代打」改为「Bot · {打法名}」；头像沿用灰色 Bot 样式（`rm-avatar bot`）。

### 3.3 托管与托管打法预设（P6/断线 + 设置弹层）

- 托管为掉线真人代打；牌桌 pinfo「托管」徽章不变（见 [06](./06-断线重连与托管.md)）。
- **托管打法默认保守**；玩家可在**设置弹层**「断线托管打法」行预设自己掉线时所用打法（FR-AI-10），未预设=保守。预设持久化（FR-AI-11）。

## 4. 机器人打法档案（Personas）

> 打法 = 策略 + 难度配置的产品化封装（对应逻辑设计 §7「人格/难度参数矩阵」）。上线按 BL-031 阶段推进，未上线者在面板锁定展示。

| 打法名（对外） | 策略内核 | 风格描述（面板文案） | 上线阶段 | P1 面板态 |
|---|---|---|---|---|
| **新手陪练** | efficiency（高扰动） | 会打但常失误，适合新手练习 | P1 | ✅ 可选 |
| **最大概率打法**（默认/推荐） | efficiency（标准） | 追求最快听牌与最高和率，稳健的"最大概率"打法 | P1 | ✅ 可选（默认高亮）|
| **追求大牌** | bigHand | 宁可慢一点，也要冲清一色/碰碰胡等高台大牌 | P2 | 🔒 敬请期待 |
| **稳健高手** | balanced | 攻防一体，危险时弃和保子，机会时果断进攻 | P3 | 🔒 敬请期待 |
| **概率大师** | monteCarlo | 蒙特卡洛模拟期望最优，接近高手的"算牌"打法 | P4 | 🔒 敬请期待 |
| **托管（保守）** | efficiency（最保守配置） | 掉线代打默认档：只摸打、不吃碰杠胡，不主动吃亏 | P1 | 不在陪玩面板出现；玩家在设置弹层预设（默认保守）|

**参数对应**（详见逻辑设计 §7）：`新手陪练`=高 `noise`；`最大概率打法`=标准 `aggression/scoreWeight`、低 `noise`；`托管`=最低 `aggression`、危险即过、不副露。

## 5. 关键流程

```
房主陪玩：等待页 → 点「添加机器人」→ 打法选择面板（默认高亮「最大概率打法」）
          → 选打法 → 「添加」→ Bot 入座（座位标签「Bot·{打法名}」）→ 计数+1（≤3）
对局中：轮到 Bot → AutoPlayer.decide(ctx) 按所选打法出招（合法动作内选择）
        → 决策延迟 thinkMs 后提交（拟人 + 复用现有去重键，避免重复广播）
断线托管：真人掉线 60s → 绑定「托管（保守）」打法代打 → 玩家重连立即接管
开发补齐：网关 AUTO_BOTS>0 → 空位补默认打法 Bot（无交互）
```

## 6. 数据与状态

- **打法标识**：每个 Bot 记录其 `personaId`（如 `efficiency-normal`）；随房间成员信息广播，用于座位标签展示。
- **持久化（FR-AI-11，已落地）**：落库于 `rooms` 表两个 JSON 列——`bot_personas`（`{seat: personaId}` Bot 打法）与 `trustee_personas`（`{userId: personaId}` 玩家托管预设）；roomActor 在 `addBot`/`updateBotPersona`/`setTrusteePersona`/`updateRoom` 时经弱依赖 hook `onRoomMeta` 增量写库（`updateRoomMeta`，MySQL/内存双实现）。重连命中内存房即恢复；服务重启经 `rebuildRoomFromStore` 读回注入 `RoomRestore.botPersonas/trusteePersonas` 恢复。未设置回落默认（Bot=最大概率打法、托管=保守）。FR-房间-12 的局数/玩法改动同路径落库。
- **协议**：`addBot` 指令增可选 `personaId`；新增 `updateBotPersona`（改已添加 Bot）；`roomView` 成员项增 `botPersona?`/`trusteePersona?`（前向兼容，缺省=默认）。**协议演进遵循既有 TableState/ViewState schema 演进约定**。
- **无积分/隐私暴露**：打法仅为风格标签，不涉及积分或隐私。
