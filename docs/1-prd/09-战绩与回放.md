## 1. 模块目标

好友俱乐部局的**复盘与争议核对**：任何一位参赛者可以重看自己参加过的每一局牌的全过程（发牌→摸打→吃碰杠→胡/荒庄）。回放是**只读**的历史重演，不影响任何实时对局；管理后台（二期 admin 子系统）将复用同一回放能力获得全量仲裁视角。

## 4. 交互与页面

- **P9 回放列表**（大厅进入）：房间卡列表（倒序）→ 展开/进入局列表；局行点击进 P10。空态文案「还没有对局记录」。
- **P10 回放播放器**：复用牌桌布局（四家手牌区/牌河/副露/事件横幅），底部播放控制条（⏮ 关键帧 / ⏯ / ⏭ 单步 / 倍速 / 进度条 / 局信息「第 N 局 · 结束方式」），顶栏「全亮」开关与退出钮。
- 回放中**不显示**任何操作按钮与响应框；事件横幅复用对局文案（碰/杠/胡/荒庄/托管等）。

## 5. 数据与协议（设计）

- 数据源：事件溯源已落库的 `games` + `game_initial_states` + `actions`（M-A2）；回放 = 客户端 `rehydrate(snapshot)` 后按序 `applyAction` 重演（引擎确定性保证逐帧一致）。
- 协议（WS，实现时落 protocol）：
  - `replayList`（req）→ `replayList`（res）：`{ rooms: [{ roomId, createdAt, rounds: [{ gameId, roundNo, endType, winnerSeats, taiBySeat, at }] }] }`（仅含本人参赛房间/局）；
  - `replayLoad { gameId }`（req）→ `replayData { gameId, snapshot, actions }`（服务端校验请求者 ∈ 该局参赛四方，否则 ack 失败）。
- 服务端：纯查询（`listGames/listActions/getInitialState` 已备），无新存储；权限校验在网关层。
