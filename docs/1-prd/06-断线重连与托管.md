## 1. 模块目标

弱网/意外退出不应毁掉一整场：掉线后**保留座位**、允许**重连完整恢复**对局；长时间未归则**托管**代打（保守策略，不主动吃碰杠胡），既不阻塞其余三家，也不损害掉线方利益。服务端持久化保证**宕机也能恢复**。

## 3. 关键流程

### 3.1 掉线 → 重连

```
玩家掉线（WS 断开）→ 服务端标记座位「离线」+ 保留 60 秒（D-24）+ 广播其余三家
 ├─ 60 秒内重连：会话校验（session token）→ 读房间快照 + 事件溯源还原对局
 │    → 下发该玩家完整视图（手牌/牌河/轮次/积分）→ 接管继续
 └─ 超时：进入托管（见 3.2）
```

### 3.2 托管

```
托管玩家：由服务端代打
 → 轮到自己：自动摸牌 → 打「安全牌」（骨架：暗牌第一张，见客户端 bot 策略）
 → 响应阶段：一律「过」（不主动吃/碰/杠/胡，保守不吃亏）
 → 直至其重连返回（立即接管）或本局结束
```

### 3.3 宕机恢复

- 服务端重启后，从 MySQL（权威对局记录）+ Redis（房间快照/会话）恢复未散场的房间与进行中的对局（依赖 FR-断线-06 持久化）。**BL-016 已落地**：成员重进触发 `rebuildRoomFromStore` 事件溯源重建（座位/积分账本/局中现场恢复，未重连者转托管），见 [`../3-技术文档/AC麻将-服务端网关与房间.md`](../3-技术文档/AC麻将-服务端网关与房间.md) §12。

### 3.4 开局/局间仪式中的离线与恢复（BL-017：已修补当前发现缺项，浏览器视觉验收受阻）

- 仪式的自动代操作与普通行牌的 **60 秒离线转托管**是两套计时，不改变座位保留、保守代打策略。轮到 Bot/离线/已托管玩家时准备 **600ms** 后自动掷骰或保留当前座位；真人正常输入期限 **10000ms**。
- **主动退出与掉线入口一致**：网关收到 `leave` 时，`phase=seating`（首局仪式）与 `phase=playing` 均调用完整 `playerDisconnected`：保留成员/座位、标记离线并广播，沿既有离线期限接续托管；不可仅清连接而漏记 `offlineSince`。退出后清除该会话的房间绑定，允许原成员重入；重复退出或先掉线再退出不覆盖已有离线起点。普通 `waiting` 的 `removePlayer` 原逻辑不变，仅清连接并保留座位，不新增离线托管计时。
- **首局仪式掉线接续**：RoomActor 记录最初 `offlineSince`，首局发牌进入 playing 后，按 `max(0, offlineSince + trusteeAfterMs - 当前时间)` 接续托管剩余等待；已过原期限则不再额外等待。`trusteeAfterMs` 正式值仍为 **60000ms**，不是发牌后重新给 60 秒，也不是将规则改为 600ms。重复 disconnect 不覆盖离线起点、不延后期限、不卸掉已接管的托管连接，避免仪式转 playing 后漏托管。
- 真人在仪式输入期间掉线或转托管，剩余等待缩短为 **min(原剩余时间, 600ms)**；不得延后已近到期的输入，不影响正在播放的滚动/结果/汇总时长。重连可在仍有效的输入期接管，但不重置或延长期限。
- 掷骰流程由服务端逐家门控：每家滚动 **1200ms**、选位结果 **2000ms**；排名/同点汇总 **2000ms**、落座汇总 **1500ms**；定庄/局间结果 **3000ms** 后才能发牌。掉线不让房间等待全员观看确认，也不能跳过完整服务端结果期。
- 重连、刷新重入、后台回前台直接呈现当前仪式步骤、操作者、已揭晓两骰及总和、重掷旧结果、最新落座与剩余时间；已落定立即显示，不重播已错过的历史掷骰，不重复弹出整个面板。仪式早于等待页订阅到达时，页面进入须检查缓存并切牌桌。
- **权威重入资料**：新版 `addPlayer` 对既有成员重绑并清离线/托管后，**先向本人发送完整 `roomView`，再 `broadcastAll`**；前者含各家 userId/nickname/isBot、玩法 settings 与当前仪式 seating，playing 下后者继续发 gameView。局间刷新无需用 placeholder 猜真人/Bot/墙模式。旧服务端仅发 gameView 时的占位 room 仅作房号/路由兼容，不视为完整身份资料。
- 「我」以稳定用户身份匹配当前仪式；首局取最新房间成员视图，局间使用当前对局视图的庄家/子数与新补发的权威房间身份/玩法，防选座重排或旧局缓存导致认错人。等待页进入时检查缓存；「再来一局」先清旧房、旧对局及仪式时钟再创建，避免旧 playing 缓存触发误路由。服务端最终裁决输入权限及过期/重复操作。
- 弱网/后台可能错过动画，恢复正确当前结果即可；退出/散场清理本页动画与计时器。本轮仅覆盖**在线服务端内存仪式**的重连恢复，**不扩展宕机后的仪式持久化恢复**，不得套用 §3.3 的已开局恢复承诺。
