## 1. 模块目标

弱网/意外退出不应毁掉一整场：掉线后**保留座位**、允许**重连完整恢复**对局；长时间未归则**托管**代打（保守策略，不主动吃碰杠胡），既不阻塞其余三家，也不损害掉线方利益。服务端持久化保证**宕机也能恢复**。

## 3. 关键流程

### 3.1 掉线 → 重连

```
玩家掉线（WS 断开）→ 服务端标记座位「离线」+ 保留 60 秒（D-24）+ 广播其余三家
 ├─ 60 秒内重连：会话校验（session token）→ 读房间快照 + 事件溯源还原对局
 │    → 下发该玩家完整视图（手牌/牌河/轮次/积分）→ 接管继续
 └─ 超时：进入托管（见 3.2）
```

### 3.2 托管

```
托管玩家：由服务端代打
 → 轮到自己：自动摸牌 → 打「安全牌」（骨架：暗牌第一张，见客户端 bot 策略）
 → 响应阶段：一律「过」（不主动吃/碰/杠/胡，保守不吃亏）
 → 直至其重连返回（立即接管）或本局结束
```

### 3.3 宕机恢复

- 服务端重启后，从 MySQL（权威对局记录）+ Redis（房间快照/会话）恢复未散场的房间与进行中的对局（依赖 FR-断线-06 持久化）。

## 4. 数据与状态

- **会话**：Redis `sess:<token>`（登录建立，TTL）；M-I 改为**服务端签发 session token** 用于重连校验（当前 mock token，见 [`../3-技术文档/AC麻将-登录鉴权.md`](../3-技术文档/AC麻将-登录鉴权.md) §4.3）。
- **房间快照**：Redis `snap:<room>`（实时态）；**对局还原**：MySQL `games`/`game_initial_states`/`game_actions` + `replayRound`（见 [`../3-技术文档/AC麻将-数据持久化与事件溯源.md`](../3-技术文档/AC麻将-数据持久化与事件溯源.md)）。
- **离线/托管态**：作为房间/对局状态的一部分广播给其余玩家（牌桌显示「离线」/「托管」标识，见 [04-对局与牌桌.md](./04-对局与牌桌.md) §4）。

## 5. 依赖与边界

- **依赖**：持久化与事件溯源（还原基座，M-A2 已备）；服务端网关与房间（座位/退房/状态广播）；登录鉴权（会话与重连校验）；网络层（`onClose` 检测与重连）。
- **边界（不在本模块）**：座位保留的触发来自房间生命周期（[03-房间系统.md](./03-房间系统.md) FR-房间-06）；托管代打的动作合法性仍由对局引擎/服务端裁决（[04-对局与牌桌.md](./04-对局与牌桌.md)）；房主掉线权限转移规则细化 → 开放问题 Q3。
