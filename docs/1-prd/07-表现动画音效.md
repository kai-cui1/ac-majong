## 1. 模块目标

在**不改变服务端权威结果**的前提下，用动画与音效把「发牌 / 摸打 / 吃碰杠胡 / 结算」表现得清晰、有节奏、有反馈感。表现层是纯客户端的**事件驱动演出**：消费服务端下发的事件流，播放对应动画/音效，演出结束后同步到最新视图。

## 3. 表现清单

### 3.1 对局动画

- **发牌**：牌墙 → 各家起手牌逐张发出（庄家 17 / 闲家 16）。
- **摸牌**：当前家从牌墙摸入一张（暗牌）。
- **打牌**：手牌选中 → 飞入中央牌河。
- **吃 / 碰 / 杠**：亮明副露飞向对应家 + 动作提示（碰/杠字样）。
- **胡牌**：胡牌方高亮 + 推倒亮牌演出。
- **荒庄**：牌墙耗尽提示。

### 3.2 音效

音效分三类，均为**事件驱动**：牌张拟音与番种语音消费服务端下发的 `GameEvent`（见 [`../3-技术文档/AC麻将-客户端网络层.md`](../3-技术文档/AC麻将-客户端网络层.md)），系统/UI 音在客户端本地触发；全部受**静音开关**控制（见 [08-规则页与设置.md](./08-规则页与设置.md)）。**不做 BGM**。

#### 3.2.1 事件 → 音效映射

| 分类 | 音效（资源名） | 触发源 | 说明 |
|---|---|---|---|
| 牌张拟音 | 打牌 `discard` | `GameEvent.discarded` | 核心，出牌飞入牌河 |
| | 摸牌 `draw` | `GameEvent.drawn` | 轻拟音 |
| | 补花 `flower` | `GameEvent.flower` | |
| | 发牌 `deal` | 开局状态切换（一次性） | |
| 番种语音 | 吃 `chi` | `GameEvent.melded`（`move='chi'`） | 中文语音 |
| | 碰 `pong` | `GameEvent.melded`（`move='pong'`） | 中文语音 |
| | 杠（明杠）`kong_exposed` | `GameEvent.kong`（`kind='exposed'`） | 中文语音「杠」 |
| | 暗杠 `kong_concealed` | `GameEvent.kong`（`kind='kong_concealed'`） | 中文语音「暗杠」，**与明杠区分** |
| | 补杠 `kong_added` | `GameEvent.kong`（`kind='kong_added'`） | 中文语音「补杠」，**与明杠区分** |
| | 胡了 `win` | `GameEvent.win` | 中文语音「胡了」，**自摸/点炮不区分**（引擎两者均发 `win`） |
| | 诈胡 `zhahu` | `GameEvent.zhahu` | 中文语音「诈胡」 |
| | 荒庄 `exhaustive` | `GameEvent.exhaustive` | 中文语音「荒庄」 |
| 系统/UI | 按钮点击 `click` | `uiButton` TOUCH_END 统一注入 | 全局一处生效 |
| | 可响应提示 `alert` | `GameEvent.responseNeeded` | 轮到本家可吃/碰/杠/胡时提醒 |
| | 倒计时警告 `countdown` | 牌桌本地（剩余 ≤5s） | |
| | 结算 `settle` | `GameEvent.roundEnd` / 结算浮层 | 胜负/积分结算 |

> **杠三种区分**：明杠语音「杠」、暗杠「暗杠」、补杠「补杠」——依据 `kong.kind`。**胡统一**：`win` 事件不区分自摸/点炮，统一播「胡了」。

#### 3.2.2 素材来源

- **牌张拟音 + 系统/UI 音**：Pixabay Sounds（royalty-free，可商用、无需署名）。
- **番种中文语音**（吃/碰/杠/暗杠/补杠/胡了/诈胡/荒庄）：Edge-TTS 本地生成，风格统一、可商用。
- 资源目录 `client/ac-majong/assets/resources/audio/`，格式 mp3（微信小游戏兼容最佳）。命名与加载约定见技术方案 [`../3-技术文档/AC麻将-前端基座与设计系统.md`](../3-技术文档/AC麻将-前端基座与设计系统.md)「音频子系统」章节。

### 3.3 结算动画

- 台数明细**逐条飞入**（番种 + 台数）；各家积分**跳动**到最新值（正负分色）。

## 4. 技术取向

- **事件驱动演出**：网络层 `onEvent` 下发 `GameEvent[]`（见 [`../3-技术文档/AC麻将-客户端网络层.md`](../3-技术文档/AC麻将-客户端网络层.md)），表现层按事件类型排队播放动画；播放期间锁定输入，结束后以最新 `ViewState` 校准，保证**演出与权威状态一致**。
- **渲染基座**：复用前端基座 `UiKit`/`Theme` 与牌桌 `TableView`/`TileNode`（见 [`../3-技术文档/AC麻将-前端基座与设计系统.md`](../3-技术文档/AC麻将-前端基座与设计系统.md)）；动画用 Cocos `tween`，音效用 `AudioSource`（封装为 `AudioManager` 单例，SFX 用 `playOneShot` 支持并发；静音偏好 `sys.localStorage` 持久化）。
- **视觉精修**：渐变贴图、中式字体、光影等在 M-E 统一处理（前端基座当前以「纯色 + 描边」近似，见其 §9）。

## 5. 依赖与边界

- **依赖**：对局流程引擎（事件类型来源）；网络层（`onEvent`/`onView`）；前端基座（渲染组件与设计令牌）；结算（结算动画数据）。
- **边界（不在本模块）**：玩法与结果由服务端权威决定，表现层**不做任何规则判定**；静音开关的 UI 归 [08-规则页与设置.md](./08-规则页与设置.md)；牌桌信息架构归 [04-对局与牌桌.md](./04-对局与牌桌.md)。
