## 1. 模块目标

在**不改变服务端权威结果**的前提下，用动画与音效把「发牌 / 摸打 / 吃碰杠胡 / 结算」表现得清晰、有节奏、有反馈感。普通行牌表现层为客户端**事件驱动演出**：消费服务端事件流，播放动画/音效后同步最新视图。**开局/局间仪式例外：服务端控制步骤与最短观看时间，客户端依展示快照演出，不以本地动画完成来决定发牌或推进业务阶段。**

## 3. 表现清单

### 3.1 对局动画

- **发牌**：牌墙 → 各家起手牌逐张发出（庄家 17 / 闲家 16）。
- **摸牌**：当前家从牌墙摸入一张（暗牌）。
- **打牌**：手牌选中 → 飞入中央牌河。
- **吃 / 碰 / 杠**：亮明副露飞向对应家 + 动作提示（碰/杠字样）。
- **胡牌**：胡牌方高亮 + 推倒亮牌演出。
- **荒庄**：牌墙耗尽提示。

### 3.1.1 开局/局间掷骰仪式（BL-017 开局仪式与摸牌位骰：已修补当前发现缺项，浏览器视觉验收受阻）

- **逐家而非并行**：从房主起沿仪式开始时下手座序轮转，高亮当前昵称与「当前操作」标识，其余禁用；真人输入 10000ms，Bot/离线/托管准备 600ms。
- **完整观看节奏**：每家滚动 **1200ms**、骰面 **90ms** 跳变，真实两枚骰子及总和停留 **2000ms** 再换人；落定缩放 **90ms达1.03峰值、200ms回1，分段CSS ease**，包含在停留内。已揭晓结果不随下一家消失。中间动画可用本地随机数，最终骰面必须取权威结果，禁止从总和拼造；旧协议缺两骰时只显示总点数。
- **汇总与重掷**：每轮最后一家的 **2000ms** 结果期结束后，才比较全体最新总和；无同点进入最终 `summary-ranking` **2000ms**，有同点进入同点/旧结果 `summary-reroll` **2000ms**。仅同点者按原轮转序逐家重掷，每家仍完整 1200ms+2000ms；旧结果标「上次／待重掷」直到本人再次落定，每轮含未重掷者重新判同点。原型旧 `order` 留存、最后一个 `rerollId` 在落定时先被移除曾令排名判断在结果期提前生效，现已修补展示门控，末次重掷result不宣布最终名次；现有 u1/u2 重掷为9、与未重掷 u0=9 撞点的 fixture 保留不改。所有重掷 `input / rolling / result` 均禁止最终名次、最大者及其高亮；header 只报重掷待比较，不能把旧顺序叫作最终选位顺序。只有无同点最终 `summary-ranking` 及其后选座阶段可显示最终排名；同点汇总仅可显示「本轮点数顺序（同点未决）」。
- **选座与定庄**：最大者选座后落座汇总 **1500ms**；首局 A 一次骰同时定庄/定开牌点，滚动 **1200ms**、结果 **3000ms**，庄家金光 **1000ms** 包含在结果期内，不额外延长。局间启用摸牌位骰时同节奏，由当前庄家操作；关闭则沿用直接续局。
- **视觉固定**：844×390 内 640×330 金色面板，选位/选座四横卡，定庄/局间罗盘（上北下南左西右东），昵称单行省略并保留「我」/机器人/操作者标识；骰面、解释与按钮区分带。physical 墙条右端跳 N 组、第 N+1 组开摸；random 不绘虚构物理位置。
- **徽章分带**：118×46 罗盘卡与现有面板预算不变；风位圆徽保留 `top:-8px; right:-6px`、20×20，Cocos 相对卡中心 **x55、y21**。庄徽从 `top:0; right:-35px` 改为 **`top:auto; bottom:0; right:-35px`、高14px**，Cocos 相对卡中心 **x76、y-16**；上下错开，避免边缘重叠，不挪动风位圆徽。
- **可见按钮状态**：非选座阶段主钮不因禁用而消失；自己真人输入期显示可用「掷骰」，非自己输入显示禁用「等待当前玩家」，滚动显示禁用「掷骰中…」，选位 `result` 显示禁用「查看结果」，定庄/局间 `result` 显示禁用「即将自动发牌」，非选座summary显示禁用「仪式进行中…」；时钟独占74px槽。选座输入与落座 `summary-seated` 均保留四个选座钮，落座汇总四钮全禁用、选定座仍为金色描边/文字/底色/光晕；沿用原型禁用与选中样式，不删节点代替禁用，不新增确认步骤。
- **长名入口与动效对齐**：原型昵称已有完整名 `title`；Cocos 已实现悬停/点击昵称显示完整名Tooltip，2秒后自动关闭，也可移开/点击提示关闭，不扩卡、不暂停计时、不增加用户确认。首步骤250ms淡入（后续/恢复不重播）、骰子0/125/250/375/500ms线性旋转/缩放关键帧（Cocos Y轴相反时旋转取反）、90ms跳面；落定90ms峰值/200ms终点按分段CSS ease。庄光1000ms用外发光半径14→24→14表达；pending文字10px弱色普通字重，自己的输入提示金色粗体、1秒ease-in-out脉冲。当前明确缺项已修补，脚本断言不等于动效观感通过。
- **同步与生命周期**：面板只在新仪式进入时弹出，步骤增量更新，不每次广播重建；重复步骤广播不重置动画/倒计时。重连/后台返回显示当前步骤剩余进度，不补播历史；退出取消本页动画与回调。每个新step通过Node.off/on重绑捕获token的按钮闭包；TOUCH_START跨step到TOUCH_END拒绝，disposed后旧回调无效。完整结果期结束前不发牌、不启动新局 Bot，不增加跳过、倍速或全员确认。产品流程以 PRD04 §4.1 为准。
- **本轮验证边界**：最终UI/client-core **100 pass**为AST真实生产类+严格mock，验证生命周期、节点状态和绘制指令，**非GPU/真实字体/截图**；原型专项agent为 **10 scenario / 131状态 + 6门控** 的JS/节点替身验证，非Browser视觉。浏览器连续三轮目标turn均 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`、hidden/attached=false；用户已打开仍不可用，`window.open`返回false，rAF暂停导致Cocos无scene。当前属于**无法生成必要验收证据的外部阻塞**，实机、真实双端/截图未完成；用户8080未重启。本次仅回填文档，不操作浏览器、启停服务或重跑验证；历史记录不倒写，详见 [BL-017流水](../5-backlog/README.md#bl-017-开局仪式与摸牌位骰实现与验证流水)。

### 3.2 音效

音效分三类，均为**事件驱动**：牌张拟音与番种语音消费服务端下发的 `GameEvent`（见 [`../3-技术文档/AC麻将-客户端网络层.md`](../3-技术文档/AC麻将-客户端网络层.md)），系统/UI 音在客户端本地触发；全部受**静音开关**控制（见 [08-规则页与设置.md](./08-规则页与设置.md)）。**不做 BGM**。

#### 3.2.1 事件 → 音效映射

| | 补花 `flower` | `GameEvent.flower` | |

| 番种语音 | 吃 `chi` | `GameEvent.melded`（`move='chi'`） | 中文语音 |
| | 碰 `pong` | `GameEvent.melded`（`move='pong'`） | 中文语音 |

### 3.3 结算动画

- 台数明细**逐条飞入**（番种 + 台数）；各家积分**跳动**到最新值（正负分色）。

## 4. 技术取向

- **仪式快照驱动**：以 `seating.presentation` 的 `ceremonyId/stepId/startedAt/deadline/serverNow` 对齐当前步骤，时间统一毫秒；只演出当前快照，不用普通行牌事件队列补播仪式历史（契约见客户端网络层 §5.2）。
- **事件驱动演出**：网络层 `onEvent` 下发 `GameEvent[]`（见 [`../3-技术文档/AC麻将-客户端网络层.md`](../3-技术文档/AC麻将-客户端网络层.md)），表现层按事件类型排队播放动画；播放期间锁定输入，结束后以最新 `ViewState` 校准，保证**演出与权威状态一致**。
- **渲染基座**：复用前端基座 `UiKit`/`Theme` 与牌桌 `TableView`/`TileNode`（见 [`../3-技术文档/AC麻将-前端基座与设计系统.md`](../3-技术文档/AC麻将-前端基座与设计系统.md)）；动画用 Cocos `tween`，音效用 `AudioSource`（封装为 `AudioManager` 单例，SFX 用 `playOneShot` 支持并发；静音偏好 `sys.localStorage` 持久化）。
- **视觉精修**：渐变贴图、中式字体、光影等在 M-E 统一处理（前端基座当前以「纯色 + 描边」近似，见其 §9）。

## 5. 依赖与边界

- **依赖**：对局流程引擎（事件类型来源）；网络层（`onEvent`/`onView`）；前端基座（渲染组件与设计令牌）；结算（结算动画数据）。
- **边界（不在本模块）**：玩法与结果由服务端权威决定，表现层**不做任何规则判定**；静音开关的 UI 归 [08-规则页与设置.md](./08-规则页与设置.md)；牌桌信息架构归 [04-对局与牌桌.md](./04-对局与牌桌.md)。
