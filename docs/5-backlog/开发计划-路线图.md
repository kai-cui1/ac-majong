## 二、已锁定的推进决策

- **D1 基座先行**：先做前端基座（M-A）+ 后端持久化基座（M-A2），再逐页还原。
- **D2 牌桌按玩家流程排**（登录→大厅→房间→牌桌），不提前。
- **D3 微信真实登录 / 云托管部署 / 微信构建** 集中到 M-K 上线阶段；本地先用 mock 跑通全流程。
- **D4 前端个人历史战绩页（profile）延后**；但后端从第一局起全量持久化。
- **D5** 架构方案第14章里程碑迁入本文件（已完成）。
- **D6（arch v2）持久化**：Redis + MySQL；对局只存业务事实（事件溯源）可真实还原；永久保留；~1000 局/天；积分随房间生命周期、不做账户钱包；前端回放 UI 优先级低。
