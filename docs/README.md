# A&C 麻将小游戏 · 文档总纲

本目录（`docs/`）是项目唯一的文档源。所有功能开发遵循「**文档先行**」规范与「**文档结构三原则**」。

## 一、开发规范（强制）

每个功能的开发、以及后续的优化迭代，必须按以下顺序推进，**禁止不写文档直接改代码**：

1. **PRD 设计**（[`1-prd/`](./1-prd/README.md)）：定义产品「做什么 / 怎么做」。若修改已有功能，则更新对应**模块 PRD** 的内容，而不是新开文件或另起说明。
2. **技术方案设计**（[`3-技术文档/`](./3-技术文档/README.md)）：定义技术上「怎么实现」。
3. **编码实现**：与文档保持一致；实现中若发现设计需调整，回头更新对应文档（融入正文，不打补丁）。

> 「什么时候做」（版本 / 迭代 / 里程碑 / 排期 / 待办）不属于 PRD 或技术方案，统一维护在 [`5-backlog/`](./5-backlog/README.md)。

## 二、文档结构三原则

1. **分模块成文件**：一个模块一个文件；模块间若有依赖或引用，通过**相对文件路径**链接引用其它文件（例：`[登录 PRD](../1-prd/01-登录与身份.md)`）。
2. **全量说明、不打补丁**：一个文件就是该模块的**完整说明**。后续迭代把变更**融入正文结构**、始终保持完整，**禁止**在文末追加「补丁式」的增量说明来替代正文更新。
3. **维护记录**：每份 PRD / 技术方案文档**末尾**附一节「维护记录」，用表格简要列出变更日期与变更概要。（`5-backlog/` 待办账本与 `2-效果图/` 原型不属 PRD/技术方案，各自沿用既有约定：backlog 以「归档 + 日期」追溯、原型以「最后更新」标注。）
