## 0. 范围与记号约定

### 0.1 本规格覆盖

- 胡牌判定（17 张 / 5 副 + 1 对，含特殊型）
- 听牌判定与听牌集合枚举
- ~50 个番种的识别算法与台数取值
- 必然包含去重
- 台数汇总 → 门槛校验（≥6 / 最小胡 1→8）
- 结算（子 / 连庄 / N / 谁付谁 / 积分变动）

### 0.2 不覆盖（见其它文档）

- 联机同步、房间管理（见《联机技术架构方案》）
- UI 呈现（见 PRD 第 6 章、`docs/2-效果图`）

### 0.3 记号

| 记号 | 含义 |
|---|---|
| `hand` | 一手胡牌的完整信息（暗牌 + 明副 + 花 + 胡牌方式 + 场景） |
| `meld` | 一副牌：顺子 / 刻子（明刻、暗刻=坎）/ 杠（明杠、暗杠、加杠） |
| `pair` | 将（对子） |
| `concealed` | 暗牌（未亮明）；`revealed` = 已亮明（吃/碰/明杠） |
| `tai(S)` | 番种集合 S 去重后的台数总和 |
| `winTile` | 胡的那张牌；`winBy` ∈ {自摸, 点炮} |

## 1. 数据模型与牌张表示

### 1.1 牌张编码

| 花色 | 代码 | 取值 | 数量 |
|---|---|---|---|
| 万 | `W` | 1–9 | 各 4 张 = 36 |
| 条 | `T` | 1–9 | 各 4 张 = 36 |
| 筒（饼/丙） | `B` | 1–9 | 各 4 张 = 36 |
| 字 | `Z` | 1东 2南 3西 4北 5中 6发 7白 | 各 4 张 = 28 |
| 花 | `H` | 1–8 | 各 1 张 = 8 |

- **牌唯一 ID**：`<花色代码><点数>`，如 `W1`（一万）、`B9`（九筒）、`Z5`（中）、`H3`（3 号花）。
- **牌墙总数**：36×3 + 28 + 8 = **144**（与 D-09 一致）。
- **数牌（万/条/筒）** 可组顺子；**字牌、花** 不可组顺子。
- **九筒 `B9` / 九万 `W9`** 为高价值特殊牌（见 3.9）；**九条 `T9` 不在特殊系列**。

### 1.2 手牌与副的表示

```
Hand {
  concealed: Map<TileId, int>        // 暗牌：每种牌的张数
  melds: List<Meld>                  // 已成型副（含亮明与暗杠）
  flowers: List<TileId>              // 花区（摸到即亮、补摸）
  winTile: TileId                    // 胡的那张
  winBy: "zimo" | "dianpao"          // 自摸 / 点炮
  fromSeat: int                      // 点炮来源（自摸为空）
  isDealer: bool                     // 胡牌方是否庄家
  // 场景上下文（结算用）
  wallRemaining: int                 // 牌墙剩余可摸张数
  lianzhuangCount: int               // 连庄次数 n
  seatsZi: Map<seat, int>            // 各家桌上「子」数
}

Meld {
  type: "chi" | "pong" | "kong_exposed" | "kong_concealed" | "kong_added"
  tiles: List<TileId>                // chi=3顺, pong=3刻, kong=4
  isConcealed: bool                  // 暗刻(坎)/暗杠 → true
}
```

> **杠与张数**：逻辑结构恒为「5 副 + 1 对」；杠占 4 张物理牌，因开杠补摸，**物理张数 = 17 + 杠数**。胡牌判定按**逻辑副**计（杠=1 副）。⚠️ 该物理张数口径在 M0 用测试用例校验。

### 1.3 派生量（供番种识别）

- `allMelds` = `melds` + 由 `concealed` 分解出的暗副（含将）。
- `pungCount` / `seqCount` / `pairCount`：刻子/顺子/对子数量。
- `concealedPungCount`（暗坎数 = 暗刻数 + **暗杠数**，N3；**点炮胡时由胡牌张凑成的第三张刻子不计**，2026-09-18 用户确认）、`kongCount`（明杠/暗杠数）。
- `suitSet`：手牌出现的数牌花色集合（判断缺一门/混一色/清一色）。
- `hasHonor` / `honorPungs`：是否含字、字刻列表。
- `flowerCount`：花数。
- `isMenqing`：门清 = 无吃/碰/明杠（**暗杠不破门清**，N2）。

## 2. 胡牌判定算法

### 2.1 判定总则

一手牌胡牌，当且仅当满足以下**任一**结构：

- **标准型**：`5 副 + 1 对`（副 = 顺/刻/杠，杠计 1 副）。
- **八对半**：见 2.3（✅ 8对+1单 或 7对+1刻，N1）。
- **十三幺**：见 2.3。

> 已成型副（`melds`）+ 暗牌分解出的副 = **5 副**；暗牌（含胡牌张）还需恰好组成 `need = 5 - len(melds)` 副 + 1 对。

### 2.2 标准型分解（递归回溯）

```
# counts: 暗牌计数(含 winTile)；need: 还需组成的副数
function canFormMelds(counts, need):
    if need == 0: return allZero(counts)
    t = smallest tileId with counts[t] > 0
    if t is None: return need == 0
    # 尝试刻子
    if counts[t] >= 3:
        counts[t] -= 3
        if canFormMelds(counts, need-1): counts[t]+=3; return true
        counts[t] += 3
    # 尝试顺子(仅数牌, rank<=7)
    if suited(t) and rank(t)<=7 and counts[t+1]>0 and counts[t+2]>0:
        dec(counts, t, t+1, t+2)
        if canFormMelds(counts, need-1): inc(counts,t,t+1,t+2); return true
        inc(counts, t, t+1, t+2)
    return false

function standardWin(counts, meldCount):
    need = 5 - meldCount
    for p in tileKinds where counts[p] >= 2:      # 枚举将
        counts[p] -= 2
        if canFormMelds(counts, need):
            counts[p] += 2
            return { pair: p, decomposition: extract(...) }   # 需回溯记录具体分解
        counts[p] += 2
    return null
```

> **实现要点**：需**枚举所有合法分解**（不止找到一个），因为不同分解会影响暗坎数、听牌型等番种；取**使台数最大**的分解（或按业务规则指定的优先序）。

### 2.3 特殊型

- **十三幺**：暗牌含**幺九字 13 种**（`Z1..Z7` + `W1/W9` + `T1/T9` + `B1/B9`）各 ≥1，其中**有且仅有一种成对**（共 14 张），**再加任意一副**（3 张）= 17。
- **八对半（30 台）** ✅（N1）：17 张可分解为 **8 对 + 1 单** 或 **7 对 + 1 刻**（两种均可）。听牌型由 2.5 通用逻辑自动判定，典型：
  - 手上 **8 对**、胡其中任一对的第 3 张（8 面听）→ 追加 **1独（1 台）**；
  - 手上 **6 对 + 1 刻 + 1 单**、单钓胡 → 追加 **独独（2 台）**。

### 2.4 将一色 / 风一色 的结构归属

将一色（2/5/8）、风一色（全字）**不是独立胡牌结构**，而是**番种**：其手牌仍按 2.2 标准型或 2.3 八对半成立胡牌，另外判定是否满足“全为 2/5/8”或“全为字”→ 计对应番（见 3.6）。

### 2.5 听牌集合枚举（供听牌型番种）

```
function waitingTiles(readyHand):        # readyHand = 16 张听牌手
    waits = []
    for t in allTileKinds:               # 34 种(数27+字7)，不含花
        if isAnyWin(readyHand.concealed + t, readyHand.melds):
            waits.append(t)
    return waits                          # |waits| 用于独独/1独 判定
```

- **独独**：`|waits| == 1`。
- **1独**：`|waits| > 1` 且 `winTile` 的牌面存在于听牌时的暗牌中（D-10）。
- **对碰**：听牌形为“两个对子等任一成刻”（按包含原则与 1独 只计 1 台，D-13）。

### 2.6 杠的处理

- 每个杠（明/暗/加）= 1 副，占 4 张物理牌；开杠后补摸一张，故**物理总张 = 17 + 杠数**。
- 胡牌判定按**逻辑副**（杠=1 副）；物理张数仅用于发牌/摸牌校验。

## 3. 番种识别规格

> 每个番种给出**算法级判定条件**与**台数**（以业务基线台数表为准）。风=`Z1..Z4`（东南西北），元=`Z5..Z7`（中发白）。`windPung/dragonPung` 指风的刻/元的刻（含碰与暗刻）。

### 3.1 花 / 字类

| 番种 | 台 | 判定条件 |
|---|---|---|
| 见花 | 1/只 | `tai += flowerCount`（每只花 1 台；八只花时不再另计，见包含） |
| 无花 | 1 | `flowerCount == 0` |
| 见字 | 1/刻 | `tai += honorPungCount`（三张同字，碰/暗刻都算；一对字=0） |
| 无字 | 1 | 手牌（含副）**无任何字牌** |
| 无花无字 | 3 | `flowerCount==0 && 无任何字牌` |

> 互斥：见花 ↔ 无花；见字 ↔ 无字。一对字既不触发见字也不触发无字（=0 台）。

### 3.2 听牌型

| 番种 | 台 | 判定条件 |
|---|---|---|
| 独独 | 2 | `abs(waits) == 1`（单钓/卡张/边张，D-16） |
| 1独 | 1 | `abs(waits) > 1 && winTile.rank ∈ readyConcealed.ranks`（D-10） |
| 对碰 | 1 | 听牌形 = 两个对子等任一成刻；与 1独 按包含只计 1 台（D-13） |

### 3.3 平

| 番种 | 台 | 判定条件 |
|---|---|---|
| 小平 | 2 | 无字 && `concealedPungCount==0` && `flowerCount>=1` && 除将外 5 副**皆顺子** |
| 大平 | 8 | 无字 && `concealedPungCount==0` && `flowerCount==0` && 除将外 5 副**皆顺子** |

### 3.4 风类

| 番种 | 台 | 判定条件 |
|---|---|---|
| 小三风 | 8 | `windPungCount==2 && windPairCount>=1` |
| 大三风 | 15 | `windPungCount==3` |
| 小四喜 | 40 | `windPungCount==3 && windPairCount>=1` |
| 大四喜 | 60 | `windPungCount==4` |
| 东风字 | 非庄2/庄3 | 手上含 `Z1`（东）刻（≥3 张）；`isDealer?3:2`；一对东不算 |

### 3.5 元类

| 番种 | 台 | 判定条件 |
|---|---|---|
| 小三元 | 15 | `dragonPungCount==2 && dragonPairCount>=1` |
| 大三元 | 30 | `dragonPungCount==3` |

### 3.6 一色与缺门

| 番种 | 台 | 判定条件 |
|---|---|---|
| 混一色 | 15 | 数牌花色`abs(suitSet)==1` **且** 含字牌 |
| 清一色 | 40 | `abs(suitSet)==1` **且** 无字牌 |
| 缺一门 | 4 | 数牌缺至少一门（`abs(suitSet)<=2`）；**被清一色/混一色吸收**（N7，见 4.3） |
| 将一色 | 40 | 手牌（含副）**全部 ∈ {各门 2/5/8}**，无字无花 |
| 风一色 | 60 | 手牌（含副）**全为字牌** `Z1..Z7` |

> 将一色/风一色 与碰碰胡 **无必然包含**（可走八对半），满足时叠加（D-07）。

### 3.7 连番类

| 番种 | 台 | 判定条件 |
|---|---|---|
| 三姊妹 | 15 | 同一门存在**三个相连刻子**（如 666/777/888） |
| 四姊妹 | 30 | 同一门存在**四个相连刻子** |
| 三相逢 | 8 | 存在点数 r，使 r,r+1,r+2 的**顺子在三门各出现一组** |
| 一条龙 | 8 | 同一门 **1–9 各一张**（123+456+789 三副顺） |

### 3.8 特殊大牌

| 番种 | 台 | 判定条件 |
|---|---|---|
| 十三幺 | 40 | 见 2.3（幺九字 13 种其一成对 + 任意一副） |
| 全求人 | 8 | `melds.length==5` 且全为**亮明吃/碰/明杠** + 单钓暗牌胡；此单钓不计独独；**含暗杠则不算**、明杠算 |
| 八只花 | 40 | `flowerCount == 8`（抓满 8 花即胡；必然包含见花） |
| 八对半 | 30 | 见 2.3（8对+1单 或 7对+1刻，N1）；听牌型另计 1独/独独 |

### 3.9 九筒 / 九万系列（仅 `B9`/`W9`）

| 番种 | 台 | 判定条件 |
|---|---|---|
| 胡九筒/九万 | 5 | `winTile ∈ {B9, W9}` |

| 自摸九筒/九万 | 10 | `winBy==自摸 && winTile ∈ {B9,W9}` |
| 暗杠九筒/九万 | 15 | 存在 `B9`/`W9` 的**暗杠** |

> 「胡九筒」与「3九筒」可叠（特例 2）；具体叠加以第 7 章特例为准。

| 番种 | 台 | 判定条件 |
|---|---|---|
| 明杠 | 1/个 | 每个明杠（含加杠）`+1` |
| 暗杠 | 2/个 | 每个暗杠 `+2`（1暗杠=2） |
| 2暗坎 | 2 | `concealedPungCount == 2` |
| 三暗坎 | 8 | `concealedPungCount == 3` |
| 四暗坎 | 15 | `concealedPungCount == 4` |

## 4. 必然包含 / 互斥矩阵

### 4.1 三种关系

| 关系 | 含义 | 处理 |
|---|---|---|
| **包含** A ⊇ B | 出现 A 必定出现 B | **只计 A、剔除 B** |
| **互斥** A ⊥ B | 不可能同时成立 | 至多计一（多由判定条件天然保证） |
| **独立** | 可各自出现 | **相加** |

### 4.2 去重算法

```
function dedup(matched):                 # matched: 已成立的番种集合
    result = set(matched)
    for A in matched:
        for B in matched:
            if A != B and ABSORBS[A].contains(B.name):
                result.remove(B)          # B 被 A 必然包含 → 剔除
    return result                          # tai = sum(t for _,t in result)
```

### 4.3 包含（吸收）清单 `ABSORBS`

| 大番 A | 吸收 B（不重复计） | 理由 |
|---|---|---|
| 八只花 | 见花 | 8 花必含花 |
| 大三元 | （其 3 个元刻的）见字 | 三元即 3 字刻 |
| 小三元 | （其 2 个元刻的）见字 | 2 字刻 |
| 大四喜 | 大三风、（4 风刻的）见字、东风字 | 4 风刻 ⊇ 3 风刻 ⊇ 东刻 |
| 小四喜 | 大三风、小三风、（3 风刻的）见字 | 3 风刻+风对 ⊇ 2 风刻+风对 |
| 大三风 | （3 风刻的）见字 | 3 风刻 |
| 小三风 | （2 风刻的）见字 | 2 风刻 |
| 无花无字 | 无花、无字 | 同属“缺失”维度（N9） |
| 大平 | 无花无字 | 大平必然无花无字（N9） |
| 将一色 | 无花无字 | 将一色定义即无字无花（N9） |
| 清一色 | 缺一门 | 清一色必缺门（N7）；**不吸收无花无字**（可能有花，N9） |
| 混一色 | 缺一门 | 混一色仅一门数牌、必缺门（N7） |
| 四姊妹 | 三姊妹 | 4 连刻 ⊇ 3 连刻 |

> ⚠️ **实例级吸收**：如大三元只吸收其 **3 个元刻** 的见字；若另有风刻，那个风刻的见字（1 台）**仍需计**。实现时按“刻实例”而非“番种名”去重，**必须用测试用例验证**。

> 🔴 **N8（编码时新发现，已修正）**：算例 1「无字(1)+小平(2)」是**叠加**计（=6），证明**平/一色类（小平/大平/清一色/将一色）并不吸收无字/无花/无花无字**（它们是不同维度的状态加成）。故上表已删除这类吸收，引擎也按此实现。

### 4.4 天然互斥（由判定条件保证，无需额外处理）

- 见花 ⊥ 无花；见字 ⊥ 无字（一对字两者都不触发）。
- 小平 ⊥ 大平（有花/无花）。
- 小三风 ⊥ 大三风 ⊥ 小四喜 ⊥ 大四喜（由 `windPungCount` 与风对唯一确定）。
- 小三元 ⊥ 大三元（`dragonPungCount`）。
- 清一色 ⊥ 混一色（有字/无字）；缺一门被清一色/混一色吸收（见 4.3，N7）。
- 将一色 ⊥ 风一色。
- 2暗坎 ⊥ 三暗坎 ⊥ 四暗坎 ⊥ 五暗坎（`concealedPungCount`）。
- 独独 ⊥ 1独（`abs(waits)` 为 1 / >1）；门清一摸一/二/三 互斥。

### 4.5 需测试验证的复杂叠加（M0 重点）

## 5. 台数计算主流程

### 5.1 输入 / 输出

- **输入**：`Hand`（第 1.2 节）+ 牌面上下文（牌墙剩余、连庄数、各家子数）。
- **输出**：`{ 总台数, 番种明细[], 是否诈胡 }`。

### 5.2 主流程伪代码

```
function computeTai(hand):
    # 1) 结构判定
    decomp = winCheck(hand)                     # 2.2/2.3；null → 无效胡
    if decomp == null: return { invalid: true }

    # 2) 枚举成立番种（实例级）
    matched = []
    matched += flowerHonorPatterns(hand)        # 3.1 见花×n/无花/见字×n/无字/无花无字
    matched += waitPatterns(hand)               # 3.2 独独/1独/对碰
    matched += structurePatterns(hand, decomp)  # 3.3~3.11 平/风/元/一色/连番/特殊/九筒九万/坎杠/补牌
    matched += menqingZimoTier(hand)            # 3.12 门清自摸覆盖档（代替基础门清/自摸）

    # 3) 特例覆盖（第 7 章）
    matched = applySpecials(hand, matched)      # 九筒九万特例、高阶番吸收基础番

    # 4) 必然包含去重（第 4 章）
    matched = dedup(matched)

    # 5) 求和
    total = sum(m.tai for m in matched)

    # 6) 最小胡 & 门槛
    if satisfiesMinimal(hand):                  # 3.13 四条件
        total = 8                               # 1 → 8
        matched.add({最小胡, 8})
    elif total < 6:
        return { zhaHu: true, total }           # 诈胡，不可胡（D-15）

    return { total, detail: matched }
```

### 5.3 门清/自摸覆盖档（关键）

```
function menqingZimoTier(hand):
    mq = isMenqing(hand); zm = (hand.winBy == 自摸)
    if mq and zm:
        if is八对半(hand) and winTile in {B9,W9}: return [门清一摸一(1)]
        elif (winTile in {B9,W9}) or is八对半(hand): return [门清一摸二(2)]
        else: return [门清一摸三(3)]
    elif mq: return [门清(1)]
    elif zm: return [自摸(1)]
    else: return []
```

> 基础「门清/自摸」**不单独叠加**到覆盖档上；但「自摸九筒/九万(10)」另计且吸收基础自摸（见第 7 章）。

### 5.4 门槛校验

- `total >= 6` → 可胡；`satisfiesMinimal` → 提升为 8；`total ∈ [2,5]` 且非最小胡 → **诈胡**（不可胡，客户端置灰/拦截）。
- **实现建议**：客户端可本地预算作 UI 提示，但**最终以服务端 `computeTai` 为准**（NFR-03）。

## 6. 结算引擎规格

### 6.1 基本量

- **积分与台数 1:1**（虚拟积分不可兑现；D-25 废除 1 台=20 倍率）。
- **N**：点炮时 `N = 胡牌方子数 + 点炮方子数`；自摸时对每一付方分别 `N = 胡牌方子数 + 该家子数`（D-17）。
- **连庄加分**：`bonus(n) = (n>=1) ? 2n-1 : 0`（即 1/3/5/7/9…，n=连庄次数，D-18）。✅ **刚上庄（n=0）不加分**（N4）。

### 6.2 最终台数公式（统一形式）

对每一（胡牌方, 付方）对：
```
taiFinal = 胡牌台数 + 3×(N+1) + ( dealerInvolved ? bonus(n) : 0 )
# dealerInvolved = 胡牌方是庄家 或 付方是庄家
```
对应业务基线三情形：①非庄胡+非庄点炮（无bonus）；②非庄胡+庄家点炮；③庄家胡。

### 6.3 谁付谁

- **点炮胡**：仅点炮方付（D-17）。
- **自摸**：其余三家各付（逐家算 N 与 bonus）。
- **一炮多响**：多家同时胡→都成立，点炮方分别向每家赔付（D-20）。

### 6.4 结算伪代码

```
function settle(winner, winType, winTai, n, seatsZi, dealerSeat):
    delta = {}                                   # seat → 积分变动
    payers = (winType==自摸) ? others(winner) : [discarder]
    for payer in payers:
        N = seatsZi[winner] + seatsZi[payer]
        dealerInvolved = (winner==dealerSeat) or (payer==dealerSeat)
        taiFinal = winTai + 3*(N+1) + (dealerInvolved ? bonus(n) : 0)
        pts = taiFinal * 20
        delta[winner] = (delta[winner]||0) + pts
        delta[payer]  = (delta[payer] ||0) - pts
    return delta
```

### 6.5 子与连庄状态转移

- **上庄**：+1 子；**每次连庄**：再 +1 子（D-18/19）。
- **清零**：自己点炮或被自摸 → 自己桌上子数清零。
- **轮转**：庄家胡→连庄（n+1）；闲家胡→下家上庄（n=0）。

### 6.6 诈胡

- 诈胡方向**其它每一家支付 300**（虚拟积分 = 15 台×20）。
- ✅ **本游戏不支持「拉」玩法**（N5）：原文“庄家被拉诈胡则拉的部分照算”不实现。

### 6.7 荒庄

- 摸到最后 4 张死牌前无人胡：**不计分、无人得失、庄家连庄**（D-21）。

## 1. 数据模型与牌张表示

### 1.1 牌张编码

| 花色 | 代码 | 取值 | 数量 |
|---|---|---|---|
| 万 | `W` | 1–9 | 各 4 张 = 36 |
| 条 | `T` | 1–9 | 各 4 张 = 36 |
| 筒（饼/丙） | `B` | 1–9 | 各 4 张 = 36 |
| 字 | `Z` | 1东 2南 3西 4北 5中 6发 7白 | 各 4 张 = 28 |
| 花 | `H` | 1–8 | 各 1 张 = 8 |

- **牌唯一 ID**：`<花色代码><点数>`，如 `W1`（一万）、`B9`（九筒）、`Z5`（中）、`H3`（3 号花）。
- **牌墙总数**：36×3 + 28 + 8 = **144**（与 D-09 一致）。
- **数牌（万/条/筒）** 可组顺子；**字牌、花** 不可组顺子。
- **九筒 `B9` / 九万 `W9`** 为高价值特殊牌（见 3.9）；**九条 `T9` 不在特殊系列**。

### 1.2 手牌与副的表示

```
Hand {
  concealed: Map<TileId, int>        // 暗牌：每种牌的张数
  melds: List<Meld>                  // 已成型副（含亮明与暗杠）
  flowers: List<TileId>              // 花区（摸到即亮、补摸）
  winTile: TileId                    // 胡的那张

  fromSeat: int                      // 点炮来源（自摸为空）
  isDealer: bool                     // 胡牌方是否庄家
  // 场景上下文（结算用）
  wallRemaining: int                 // 牌墙剩余可摸张数
  lianzhuangCount: int               // 连庄次数 n

}

Meld {
  type: "chi" | "pong" | "kong_exposed" | "kong_concealed" | "kong_added"
  tiles: List<TileId>                // chi=3顺, pong=3刻, kong=4

```

> **杠与张数**：逻辑结构恒为「5 副 + 1 对」；杠占 4 张物理牌，因开杠补摸，**物理张数 = 17 + 杠数**。胡牌判定按**逻辑副**计（杠=1 副）。⚠️ 该物理张数口径在 M0 用测试用例校验。

### 1.3 派生量（供番种识别）

- `allMelds` = `melds` + 由 `concealed` 分解出的暗副（含将）。
- `pungCount` / `seqCount` / `pairCount`：刻子/顺子/对子数量。
- `concealedPungCount`（暗坎数 = 暗刻数 + **暗杠数**，N3；**点炮胡时由胡牌张凑成的第三张刻子不计**，2026-09-18 用户确认）、`kongCount`（明杠/暗杠数）。
- `suitSet`：手牌出现的数牌花色集合（判断缺一门/混一色/清一色）。
- `hasHonor` / `honorPungs`：是否含字、字刻列表。
- `flowerCount`：花数。
- `isMenqing`：门清 = 无吃/碰/明杠（**暗杠不破门清**，N2）。

## 2. 胡牌判定算法

### 2.1 判定总则

一手牌胡牌，当且仅当满足以下**任一**结构：

- **标准型**：`5 副 + 1 对`（副 = 顺/刻/杠，杠计 1 副）。
- **八对半**：见 2.3（✅ 8对+1单 或 7对+1刻，N1）。
- **十三幺**：见 2.3。

> 已成型副（`melds`）+ 暗牌分解出的副 = **5 副**；暗牌（含胡牌张）还需恰好组成 `need = 5 - len(melds)` 副 + 1 对。

### 2.2 标准型分解（递归回溯）

```
# counts: 暗牌计数(含 winTile)；need: 还需组成的副数
function canFormMelds(counts, need):
    if need == 0: return allZero(counts)
    t = smallest tileId with counts[t] > 0
    if t is None: return need == 0
    # 尝试刻子
    if counts[t] >= 3:
        counts[t] -= 3
        if canFormMelds(counts, need-1): counts[t]+=3; return true
        counts[t] += 3
    # 尝试顺子(仅数牌, rank<=7)
    if suited(t) and rank(t)<=7 and counts[t+1]>0 and counts[t+2]>0:
        dec(counts, t, t+1, t+2)
        if canFormMelds(counts, need-1): inc(counts,t,t+1,t+2); return true
        inc(counts, t, t+1, t+2)
    return false

function standardWin(counts, meldCount):
    need = 5 - meldCount
    for p in tileKinds where counts[p] >= 2:      # 枚举将
        counts[p] -= 2
        if canFormMelds(counts, need):
            counts[p] += 2
            return { pair: p, decomposition: extract(...) }   # 需回溯记录具体分解
        counts[p] += 2
    return null
```

> **实现要点**：需**枚举所有合法分解**（不止找到一个），因为不同分解会影响暗坎数、听牌型等番种；取**使台数最大**的分解（或按业务规则指定的优先序）。

### 2.3 特殊型

- **十三幺**：暗牌含**幺九字 13 种**（`Z1..Z7` + `W1/W9` + `T1/T9` + `B1/B9`）各 ≥1，其中**有且仅有一种成对**（共 14 张），**再加任意一副**（3 张）= 17。
- **八对半（30 台）** ✅（N1）：17 张可分解为 **8 对 + 1 单** 或 **7 对 + 1 刻**（两种均可）。听牌型由 2.5 通用逻辑自动判定，典型：
  - 手上 **8 对**、胡其中任一对的第 3 张（8 面听）→ 追加 **1独（1 台）**；
  - 手上 **6 对 + 1 刻 + 1 单**、单钓胡 → 追加 **独独（2 台）**。

### 2.4 将一色 / 风一色 的结构归属

将一色（2/5/8）、风一色（全字）**不是独立胡牌结构**，而是**番种**：其手牌仍按 2.2 标准型或 2.3 八对半成立胡牌，另外判定是否满足“全为 2/5/8”或“全为字”→ 计对应番（见 3.6）。

### 2.5 听牌集合枚举（供听牌型番种）

```
function waitingTiles(readyHand):        # readyHand = 16 张听牌手
    waits = []
    for t in allTileKinds:               # 34 种(数27+字7)，不含花
        if isAnyWin(readyHand.concealed + t, readyHand.melds):
            waits.append(t)
    return waits                          # |waits| 用于独独/1独 判定
```

- **独独**：`|waits| == 1`。
- **1独**：`|waits| > 1` 且 `winTile` 的牌面存在于听牌时的暗牌中（D-10）。
- **对碰**：听牌形为“两个对子等任一成刻”（按包含原则与 1独 只计 1 台，D-13）。

### 2.6 杠的处理

- 每个杠（明/暗/加）= 1 副，占 4 张物理牌；开杠后补摸一张，故**物理总张 = 17 + 杠数**。
- 胡牌判定按**逻辑副**（杠=1 副）；物理张数仅用于发牌/摸牌校验。

## 3. 番种识别规格

> 每个番种给出**算法级判定条件**与**台数**（以业务基线台数表为准）。风=`Z1..Z4`（东南西北），元=`Z5..Z7`（中发白）。`windPung/dragonPung` 指风的刻/元的刻（含碰与暗刻）。

### 3.1 花 / 字类

| 番种 | 台 | 判定条件 |
|---|---|---|
| 见花 | 1/只 | `tai += flowerCount`（每只花 1 台；八只花时不再另计，见包含） |
| 无花 | 1 | `flowerCount == 0` |
| 见字 | 1/刻 | `tai += honorPungCount`（三张同字，碰/暗刻都算；一对字=0） |
| 无字 | 1 | 手牌（含副）**无任何字牌** |
| 无花无字 | 3 | `flowerCount==0 && 无任何字牌` |

> 互斥：见花 ↔ 无花；见字 ↔ 无字。一对字既不触发见字也不触发无字（=0 台）。

### 3.2 听牌型

| 番种 | 台 | 判定条件 |
|---|---|---|
| 独独 | 2 | `abs(waits) == 1`（单钓/卡张/边张，D-16） |
| 1独 | 1 | `abs(waits) > 1 && winTile.rank ∈ readyConcealed.ranks`（D-10） |
| 对碰 | 1 | 听牌形 = 两个对子等任一成刻；与 1独 按包含只计 1 台（D-13） |

### 3.3 平

| 番种 | 台 | 判定条件 |
|---|---|---|
| 小平 | 2 | 无字 && `concealedPungCount==0` && `flowerCount>=1` && 除将外 5 副**皆顺子** |
| 大平 | 8 | 无字 && `concealedPungCount==0` && `flowerCount==0` && 除将外 5 副**皆顺子** |

### 3.4 风类

| 番种 | 台 | 判定条件 |
|---|---|---|
| 小三风 | 8 | `windPungCount==2 && windPairCount>=1` |
| 大三风 | 15 | `windPungCount==3` |
| 小四喜 | 40 | `windPungCount==3 && windPairCount>=1` |
| 大四喜 | 60 | `windPungCount==4` |
| 东风字 | 非庄2/庄3 | 手上含 `Z1`（东）刻（≥3 张）；`isDealer?3:2`；一对东不算 |

### 3.5 元类

| 番种 | 台 | 判定条件 |
|---|---|---|
| 小三元 | 15 | `dragonPungCount==2 && dragonPairCount>=1` |
| 大三元 | 30 | `dragonPungCount==3` |

### 3.6 一色与缺门

| 番种 | 台 | 判定条件 |
|---|---|---|
| 混一色 | 15 | 数牌花色`abs(suitSet)==1` **且** 含字牌 |
| 清一色 | 40 | `abs(suitSet)==1` **且** 无字牌 |
| 缺一门 | 4 | 数牌缺至少一门（`abs(suitSet)<=2`）；**被清一色/混一色吸收**（N7，见 4.3） |
| 将一色 | 40 | 手牌（含副）**全部 ∈ {各门 2/5/8}**，无字无花 |

### 3.7 连番类

| 番种 | 台 | 判定条件 |
|---|---|---|

## 4. 必然包含 / 互斥矩阵

### 4.1 三种关系

| 关系 | 含义 | 处理 |
|---|---|---|
| **包含** A ⊇ B | 出现 A 必定出现 B | **只计 A、剔除 B** |
| **互斥** A ⊥ B | 不可能同时成立 | 至多计一（多由判定条件天然保证） |
| **独立** | 可各自出现 | **相加** |

### 4.2 去重算法

```
function dedup(matched):                 # matched: 已成立的番种集合
    result = set(matched)
    for A in matched:
        for B in matched:
            if A != B and ABSORBS[A].contains(B.name):
                result.remove(B)          # B 被 A 必然包含 → 剔除
    return result                          # tai = sum(t for _,t in result)
```

### 4.3 包含（吸收）清单 `ABSORBS`

| 大番 A | 吸收 B（不重复计） | 理由 |
|---|---|---|
| 八只花 | 见花 | 8 花必含花 |
| 大三元 | （其 3 个元刻的）见字 | 三元即 3 字刻 |
| 小三元 | （其 2 个元刻的）见字 | 2 字刻 |

## 5. 台数计算主流程

### 5.1 输入 / 输出

- **输入**：`Hand`（第 1.2 节）+ 牌面上下文（牌墙剩余、连庄数、各家子数）。
- **输出**：`{ 总台数, 番种明细[], 是否诈胡 }`。

### 5.2 主流程伪代码

```
function computeTai(hand):
    # 1) 结构判定
    decomp = winCheck(hand)                     # 2.2/2.3；null → 无效胡
    if decomp == null: return { invalid: true }

    # 2) 枚举成立番种（实例级）
    matched = []
    matched += flowerHonorPatterns(hand)        # 3.1 见花×n/无花/见字×n/无字/无花无字
    matched += waitPatterns(hand)               # 3.2 独独/1独/对碰
    matched += structurePatterns(hand, decomp)  # 3.3~3.11 平/风/元/一色/连番/特殊/九筒九万/坎杠/补牌
    matched += menqingZimoTier(hand)            # 3.12 门清自摸覆盖档（代替基础门清/自摸）

    # 3) 特例覆盖（第 7 章）
    matched = applySpecials(hand, matched)      # 九筒九万特例、高阶番吸收基础番

    # 4) 必然包含去重（第 4 章）
    matched = dedup(matched)

    # 5) 求和
    total = sum(m.tai for m in matched)

    # 6) 最小胡 & 门槛
    if satisfiesMinimal(hand):                  # 3.13 四条件
        total = 8                               # 1 → 8
        matched.add({最小胡, 8})
    elif total < 6:
        return { zhaHu: true, total }           # 诈胡，不可胡（D-15）

    return { total, detail: matched }
```

### 5.3 门清/自摸覆盖档（关键）

```
function menqingZimoTier(hand):
    mq = isMenqing(hand); zm = (hand.winBy == 自摸)
    if mq and zm:
        if is八对半(hand) and winTile in {B9,W9}: return [门清一摸一(1)]
        elif (winTile in {B9,W9}) or is八对半(hand): return [门清一摸二(2)]
        else: return [门清一摸三(3)]
    elif mq: return [门清(1)]
    elif zm: return [自摸(1)]
    else: return []
```

> 基础「门清/自摸」**不单独叠加**到覆盖档上；但「自摸九筒/九万(10)」另计且吸收基础自摸（见第 7 章）。

### 5.4 门槛校验

- `total >= 6` → 可胡；`satisfiesMinimal` → 提升为 8；`total ∈ [2,5]` 且非最小胡 → **诈胡**（不可胡，客户端置灰/拦截）。
- **实现建议**：客户端可本地预算作 UI 提示，但**最终以服务端 `computeTai` 为准**（NFR-03）。

## 6. 结算引擎规格

### 6.1 基本量

- **积分与台数 1:1**（虚拟积分不可兑现；D-25 废除 1 台=20 倍率）。
- **N**：点炮时 `N = 胡牌方子数 + 点炮方子数`；自摸时对每一付方分别 `N = 胡牌方子数 + 该家子数`（D-17）。
- **连庄加分**：`bonus(n) = (n>=1) ? 2n-1 : 0`（即 1/3/5/7/9…，n=连庄次数，D-18）。✅ **刚上庄（n=0）不加分**（N4）。

### 6.2 最终台数公式（统一形式）

对每一（胡牌方, 付方）对：
```
taiFinal = 胡牌台数 + 3×(N+1) + ( dealerInvolved ? bonus(n) : 0 )
# dealerInvolved = 胡牌方是庄家 或 付方是庄家
```
对应业务基线三情形：①非庄胡+非庄点炮（无bonus）；②非庄胡+庄家点炮；③庄家胡。

### 6.3 谁付谁

- **点炮胡**：仅点炮方付（D-17）。
- **自摸**：其余三家各付（逐家算 N 与 bonus）。
- **一炮多响**：多家同时胡→都成立，点炮方分别向每家赔付（D-20）。

### 6.4 结算伪代码

```
function settle(winner, winType, winTai, n, seatsZi, dealerSeat):
    delta = {}                                   # seat → 积分变动
    payers = (winType==自摸) ? others(winner) : [discarder]
    for payer in payers:
        N = seatsZi[winner] + seatsZi[payer]
        dealerInvolved = (winner==dealerSeat) or (payer==dealerSeat)
        taiFinal = winTai + 3*(N+1) + (dealerInvolved ? bonus(n) : 0)
        pts = taiFinal * 20
        delta[winner] = (delta[winner]||0) + pts
        delta[payer]  = (delta[payer] ||0) - pts
    return delta
```

### 6.5 子与连庄状态转移

- **上庄**：+1 子；**每次连庄**：再 +1 子（D-18/19）。
- **清零**：自己点炮或被自摸 → 自己桌上子数清零。
- **轮转**：庄家胡→连庄（n+1）；闲家胡→下家上庄（n=0）。

### 6.6 诈胡

- 诈胡方向**其它每一家支付 300**（虚拟积分 = 15 台×20）。
- ✅ **本游戏不支持「拉」玩法**（N5）：原文“庄家被拉诈胡则拉的部分照算”不实现。

### 6.7 荒庄

- 摸到最后 4 张死牌前无人胡：**不计分、无人得失、庄家连庄**（D-21）。
